## Explanations to tighten

- **Rust Level 12, p. 147.** The book says that using `FnMut` requires the queue to keep the callback for repeated execution. A native probe calls each owned `FnMut` callback once and discards it. [Manuscript](../work/manuscript/ch12.txt#L175) · [Rust FnMut](https://doc.rust-lang.org/std/ops/trait.FnMut.html)
- **Rust Level 19, p. 222.** The book says that scoped worker borrows cannot escape, but the level's boss relies on returning a borrow. A borrow of caller-owned data can outlive the scope when returned through `join`. Scope-bound handles and references to worker-local data have different limits. [Manuscript](../work/manuscript/ch19.txt#L37) · [Rust scoped thread lifetimes](https://doc.rust-lang.org/std/thread/fn.scope.html#lifetimes)
- **Rust Level 24, p. 274.** Repeating `reserve(1)` at length one cannot force repeated vector growth after the first reservation. The push and pop still move the owning handle. [Manuscript](../work/manuscript/ch24.txt#L41) · [Rust Vec::reserve](https://doc.rust-lang.org/std/vec/struct.Vec.html#method.reserve)
- **Go Level 7, p. 25.** For a single-message boundary, require the second `Decode` to return `io.EOF`. Malformed trailing input returns a syntax error even when there is no valid second JSON value. The suggested integer field also accepts `"xp":null` as zero on a fresh struct. State whether the challenge allows that alongside missing XP. [Lesson](../data/worlds/go/source.json#L240) · [Go encoding/json](https://pkg.go.dev/encoding/json#Unmarshal)

# Ferrum book and game audit

Reviewed November 7, 2026. This pass covered the 84 lessons across JavaScript, TypeScript, Rust, and Go, including the printed explanations, examples, checkpoints, challenge contracts, and GM feedback. The technical review used official language specifications and library documentation, plus executable probes for behavior that matters to the exercises. The artifact audit checks the PDFs, rendered reader pages, hyperlinks, field kits, and prompt bindings together.

| World and location | Finding and correction | Primary reference |
| --- | --- | --- |
| JavaScript 3, Arrays, Records and Missing Fields | An array can have holes. Qualified contiguous element positions as a property of dense arrays, and made the exercise's input assumption explicit. | [ECMAScript array objects](https://tc39.es/ecma262/#sec-array-exotic-objects) |
| JavaScript 6, Validate Data at the Boundary | The worked validator could accept an inherited name. The example and challenge now require the relevant fields to be own properties before checking values. | [ECMAScript Object.hasOwn](https://tc39.es/ecma262/#sec-object.hasown) |
| JavaScript 9, References, Copies and Identity | The original copy explanation did not say which object properties spread copies. It now describes own enumerable properties and keeps the challenge scoped to plain data. | [ECMAScript CopyDataProperties](https://tc39.es/ecma262/#sec-copydataproperties) |
| JavaScript 12, Async Errors and Stale Results | The request token guarded successes, but an older rejection could still reach the outer error publisher. The example and challenge now handle fulfillment and rejection before the same token check. The debrief asks the learner to test both stale outcomes. | [ECMAScript async functions](https://tc39.es/ecma262/#sec-async-function-definitions) |
| TypeScript 3, The Two Signal Flags | A discriminated union narrows a member; structural typing still allows compatible values to carry extra fields. The text separates narrowing from an exact runtime schema. | [Type compatibility](https://www.typescriptlang.org/docs/handbook/type-compatibility.html) |
| TypeScript 4, Callbacks at the Sorting Belt | Checking only for a negative input allowed `NaN` through a filter that claimed to forward nonnegative weights. The challenge uses a positive comparison. The example validates any supplied count limit and preserves a limit of zero. | [ECMAScript numeric comparison](https://tc39.es/ecma262/#sec-number::lessthan) |
| TypeScript 5 and 14, Untrusted Manifest and Harbor Dispatch | Runtime decoders now require non-array records and their own required fields. These checks keep an array or inherited property from standing in for an input record. | [TypeScript narrowing](https://www.typescriptlang.org/docs/handbook/2/narrowing.html) · [ECMAScript Object.hasOwn](https://tc39.es/ecma262/#sec-object.hasown) |
| TypeScript 9, The Registry Blueprint | The patch policy now says that an omitted or `undefined` field preserves the old value in this example, and explains the separate compiler option for rejecting an explicit `undefined`. | [exactOptionalPropertyTypes](https://www.typescriptlang.org/tsconfig/#exactOptionalPropertyTypes) |
| TypeScript 11, The Typed Message Board | The exhaustive fallback previously returned the unexpected runtime value despite promising a string. It now checks exhaustiveness with `never` and throws on an invalid tag. | [TypeScript exhaustiveness checking](https://www.typescriptlang.org/docs/handbook/2/narrowing.html#exhaustiveness-checking) |
| Rust 3, Borrow Scopes | Clarified that the reference value ceases to be used or is consumed without destroying its referent. | [Rust reference types](https://doc.rust-lang.org/reference/types/pointer.html#references-) |
| Rust 18, Constant Evaluation | Clarified disjoint storage for nonzero-sized statics, and the possible overlap of immutable static storage with objects without a unique address. | [Rust static storage disjointness](https://doc.rust-lang.org/reference/items/static-items.html#r-items.static.storage-disjointness) |
| Rust 23, Async State | A guard can remain live across `Pending` due to its destructor even if it has no explicit later read. The text describes both value use and pending destruction. | [Rust destructors and drop scopes](https://doc.rust-lang.org/reference/destructors.html) |
| Rust 24, Training encounter 2 | The question used “replace” as though it always meant returning the old value. The corrected encounter contrasts moving the old child out with `mem::replace` and dropping it in place with `Pin::set`. The native probe verifies where the old child's destructor runs. | [Pin::set](https://doc.rust-lang.org/std/pin/struct.Pin.html#method.set) |
| Rust 37, Borrowing Parser | The parser operates on one already framed line. The caller must split the stream into records; trimming the fields does not frame the stream. | [Rust str::lines](https://doc.rust-lang.org/std/primitive.str.html#method.lines) |
| Rust 41, Feature Contracts | Reproduced a tracing build panic by closing its stderr reader. The listing now performs a best-effort fallible write, preserving the function result when logging fails. The discussion uses `core::error::Error` in either feature build. | [eprintln! panic behavior](https://doc.rust-lang.org/std/macro.eprintln.html#panics) · [Write::write_fmt](https://doc.rust-lang.org/std/io/trait.Write.html#method.write_fmt) · [core::error::Error](https://doc.rust-lang.org/core/error/trait.Error.html) |
| Go, The Relay Guild | Checked slice sharing, typed nil interfaces, error chains, closed and drained channels, and cancellation against their actual contracts. The capstone uses a bounded worker set, keeps results in input order, and preserves failures. Fixed two Go pages that had split a worked example from its takeaway or encounter link. | [Go specification](https://go.dev/ref/spec) · [Go memory model](https://go.dev/ref/mem) · [context](https://pkg.go.dev/context) · [sync.WaitGroup.Go](https://pkg.go.dev/sync#WaitGroup.Go) |
| Game Master, all worlds | Saving a scratchpad or written response could display the same route recommendation as a correct quiz answer. Recommendations now appear only for choice responses and use the route's actual label. | Reproduced in the reader; covered by the Go browser journey. |
| Saved feedback, all worlds | Returning heroes could still see outdated book feedback stored with their answers. The API now gets current feedback for matching practice prompts and preserves the submitted value and recorded grader results. | Verified with a saved answer carrying obsolete feedback and a stale verdict. |

The installed app uses one XP per core mark and an optional side-quest tally. The Rust PDF's printable quest journal retains its tabletop scoring; the Rust character sheet explains the difference.

## Verification

- **JavaScript:** All 14 examples ran on Node.js 24.19.0 with expected output and edge checks. All 14 starters passed syntax checking. [Node.js releases](https://nodejs.org/en/about/previous-releases)
- **TypeScript:** All 14 examples and 14 starters passed strict checking on TypeScript 7.0.2. The examples ran as emitted JavaScript and with Node's type stripping. A separate module test exercised the type-only import and emitted JavaScript import path. [TypeScript 7 release](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/) · [Node type stripping](https://nodejs.org/docs/latest-v24.x/api/typescript.html)
- **Rust:** Rust 1.99.1 and edition 2024 accepted 144 listings and rejected 12 intended failures. Ran 122 complete examples, both book regression suites, and targeted probes for async drop, pinning, and stderr failure. All 126 training questions and answers and both appendices were reviewed. All 46 native assertions passed across the 14 graded encounters; unfinished starters and forbidden callers were checked too. [Rust 1.99.1 release notes](https://doc.rust-lang.org/releases.html#version-1991-2026-10-15)
- **Go:** All 14 examples produced the expected output and passed `go vet` on Go 1.25.1 and 1.27.3. All 14 starters compiled and ran, and the extracted table-driven test passed. On Go 1.27.3, 14 challenge probes also passed, covering overflow, slice capacity, decoding, error wrapping, cancellation, and worker limits. The race detector was unavailable on this Windows setup. [Go release history](https://go.dev/doc/devel/release) · [Go testing tutorial](https://go.dev/doc/tutorial/add-a-test)
- **App:** 41 Node checks and six Chromium tests passed, covering hero and world isolation, answer persistence, page and editor focus, guided review, and the new character sheet. The real Docker grader test was skipped because the local Linux container runner was unavailable; native Rust exercise tests passed.
- **Artifacts:** `python verify-worlds.py` passed on all 718 pages (47 JavaScript, 56 TypeScript, 559 Rust, 56 Go), checking book links, reader images, GM prompts, and field kits. It also checks all 171 fillable Rust fields. The Rust round-trip form test writes sample values, reopens the result, and checks its field and widget values. All existing quest and prompt page anchors remain where they were in the previous release.

For the earlier Rust review, including the Rust 2024 edition and new standard-library APIs, see [RUST-AUDIT.md](RUST-AUDIT.md).

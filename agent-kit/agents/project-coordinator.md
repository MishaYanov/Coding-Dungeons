# Project coordinator

Own the requested outcome, the integration branch, and the distinction between implementation and verified delivery.

Read [the repository map](../references/repository-map.md) and [validation matrix](../references/validation-matrix.md). Load the skills for the work actually requested; this role is not a reason to invoke every skill.

## Coordinate the work

- Establish the intended audience, target platforms, offline requirements, and which artifact or behavior the user wants changed. Consult existing project sources before asking for information they already contain.
- Divide independent work by files or isolated worktrees. Name the owner of shared registries, generated datasets, and the final book build. In a shared checkout, contributors do not switch branches or commit another contributor's unfinished work.
- Keep book authoring, language correctness, game integration, and package validation as distinct responsibilities. Arrange an independent review of unsafe execution boundaries and of new teaching examples.
- Reconcile stable world, hero, exercise, prompt and encounter IDs before integrating changes. A compiler pass, a UI pass, and an installed-package pass support different claims.
- Integrate feature branches into the requested release branch, resolve the final scope in release notes, and verify the files actually shipped. Follow the current user's instructions for external publication and repository changes.

## Handoff

Record the implemented behavior, changed source/generated files, exact checks and their coverage, remaining concrete limits, release branch/commit, and artifact paths/hashes when relevant. Preserve user saves and durable signing identities. Do not claim a pending CI run has passed.
